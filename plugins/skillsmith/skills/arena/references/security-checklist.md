# Security checklist

Products built quickly with AI leak data when nobody checks. In 2025 a
row-level-security gap in apps generated by one popular builder let
strangers read and write their databases (CVE-2025-48757, CVSS 9.3). Go
through this list before the manager files claims. Each item applies only if
the product has that feature.

## Secrets

- [ ] No API keys, tokens or passwords in the code or in git history.
- [ ] Secrets come from environment variables; `.env` is in `.gitignore`;
      `.env.example` lists the names with fake values.
- [ ] Nothing secret is sent to the browser. Keys in front-end code are
      public keys by design, or they do not belong there.

## Data and accounts

- [ ] Every database table that holds user data has access rules
      (row-level security, or checks in every server route) so a user sees
      only their own rows.
- [ ] Passwords are never stored; use the platform's auth or a vetted
      library with salted hashing.
- [ ] Sessions expire; logout works; password reset links are single-use.
- [ ] Admin pages check the role on the server, not only by hiding a button.

## Input

- [ ] Every input is validated on the server: type, length, format.
- [ ] Database queries use parameters, never string concatenation.
- [ ] User text shown on a page is escaped (no raw HTML injection).
- [ ] File uploads check type and size and are not executable.
- [ ] Forms that change data are protected against cross-site requests
      (same-site cookies or tokens).

## Exposure

- [ ] Error pages do not show stack traces or internal paths in production.
- [ ] Rate limits on login, sign-up, contact forms and anything that sends
      email or SMS.
- [ ] HTTPS only once deployed; cookies `Secure` and `HttpOnly`.
- [ ] Dependencies have no known critical vulnerabilities (`npm audit` or
      the stack's equivalent) at the time of the final commit.

## Payments

- [ ] Card data never touches our server; use the provider's hosted page or
      payment links.
- [ ] The amount is decided on the server, never trusted from the browser.
- [ ] Payment success is confirmed by the provider's webhook or API, not by
      a redirect alone.

## Privacy

- [ ] Collect only what the brief needs.
- [ ] If personal data is stored, the README says what, where, and how to
      delete it.
